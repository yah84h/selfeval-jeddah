# دليل النشر والتحديث (للمطوّر)

## المبدأ
- **البرنامج** يُثبَّت في مجلد التثبيت ويُستبدل بالكامل عند التحديث.
- **بيانات المدرسة** في مجلد مستقل لا يلمسه المثبِّت ولا المحدِّث:
  - Windows: `%AppData%\selfeval-jeddah\` (settings.json + data\data.db + data\evidence\ + data\backups\)
  - macOS: `~/Library/Application Support/selfeval-jeddah/`
- قبل تثبيت أي تحديث يأخذ البرنامج نسخة احتياطية `pre-update_*.zip` تلقائيًا.
- عند أول تشغيل بعد التحديث تُنفَّذ ترحيلات قاعدة البيانات الناقصة فقط (`src/main/db/migrations.ts`).

## الإعداد مرة واحدة
1. أنشئ مستودعًا على GitHub (عام أو خاص — التحديثات تعمل مع المستودع **العام** مباشرة؛ الخاص يحتاج توكن داخل التطبيق وهو غير مستحسن).
2. في `electron-builder.yml` عدّل:
   ```yaml
   publish:
     provider: github
     owner: <اسم حسابك>
     repo: <اسم المستودع>
   ```
3. ادفع المشروع إلى الفرع `main`. سيعمل `CI` تلقائيًا (فحص أنواع + اختبارات + بناء).

## إصدار نسخة جديدة
```bash
# 1) ارفع رقم الإصدار (يُحدّث package.json ويُنشئ وسمًا)
npm version patch      # 1.0.0 → 1.0.1   (أو minor / major)

# 2) ادفع الكود والوسم
git push && git push --tags
```
- GitHub Actions (`.github/workflows/release.yml`) يبني مثبِّت Windows وملفات ماك ويرفعها على **Release** باسم الوسم مع `latest.yml` و`latest-mac.yml`.
- افتح صفحة الإصدار على GitHub، اكتب ملاحظات الإصدار بالعربية (تظهر للعميل في زر التحديث)، وتأكد أن الإصدار **منشور** (ليس Draft).
- عند العميل: الإعدادات والتحديث → **التحقق من التحديثات** → تنزيل → تثبيت وإعادة التشغيل.

## البناء محليًا (بدون نشر)
```bash
npm install --legacy-peer-deps
npm run dev          # تشغيل تطويري
npm test             # اختبارات الخدمات
npm run dist:win     # مثبِّت Windows (من جهاز Windows أو عبر CI)
npm run dist:mac     # DMG لماك (من جهاز ماك)
```
المخرجات في `release/<الإصدار>/`.

## اختبار الترقية قبل النشر (مهم)
1. ثبّت الإصدار الحالي على جهاز اختبار، أنشئ ملف مدرسة وارفع عدة شواهد.
2. ثبّت الإصدار الجديد فوقه (أو عبر زر التحديث من إصدار تجريبي).
3. تأكد أن: اسم المدرسة والشواهد والنسب موجودة، ومجلد `backups` فيه نسخة `pre-update_*`.
4. شغّل «فحص سلامة البيانات» من الإعدادات.

## توقيع الكود (اختياري لكنه مستحسن)
- **Windows**: بدون توقيع يظهر تحذير SmartScreen أول مرة؛ للتوقيع أضف `CSC_LINK` و`CSC_KEY_PASSWORD` كأسرار في GitHub.
- **macOS**: بدون توقيع يجب فتح التطبيق بالزر الأيمن → فتح أول مرة. للتوقيع والتوثيق أضف شهادة Apple Developer وفعّل `hardenedRuntime` و`notarize` في `electron-builder.yml`.

## إضافة ترحيلة قاعدة بيانات
أضف عنصرًا جديدًا في `src/main/db/migrations.ts` برقم أعلى، ولا تعدّل ترحيلة منشورة أبدًا. الاختبارات (`tests/services.test.ts`) تتحقق من التطبيق السليم.
